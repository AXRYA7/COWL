# Security & Hardware Safety Policy

## 1. Hardware Safety Policy

COWL interacts directly with physical USB and Bluetooth hardware peripherals. In hardware software, safety bugs can cause permanent physical damage, EEPROM corruption, or bricked devices.

To mitigate this:
- **Strict Input Validation**: All outgoing packets constructed by COWL must pass strict bounds checking against verified schemas before being dispatched to the transport layer.
- **No Arbitrary Writes**: COWL prohibits exploratory writes and fuzzing.
- **No Firmware Flashing**: COWL does not provide or support firmware flashing capabilities, eliminating the risk of bootloader corruption.

If you discover a command or packet sequence within COWL that causes device instability, persistent misbehavior, or potential hardware damage, treat it as a critical security issue.

---

## 2. Reporting a Vulnerability

Please report security issues or hazardous hardware command flaws responsibly.

- **Do NOT** open a public GitHub issue for critical hardware safety or privilege escalation vulnerabilities.
- Submit details privately to the project maintainers via GitHub Security Advisories or by emailing the project maintainers directly.
- Include:
  - Description of the vulnerability or unsafe packet sequence.
  - Affected device models, connection modes (USB wired / 2.4GHz / Bluetooth), and firmware versions (if known).
  - Minimal reproducible steps or packet traces.
  - Potential impact (e.g., persistent configuration corruption, local privilege escalation).

Maintainers will acknowledge receipt, triage the issue, and coordinate a fix and advisory.

---

## 3. Scope & Boundaries

### In Scope
- Memory corruption, integer overflows, or boundary errors in packet decoders and serializers.
- Malformed USB/HID report handling that causes crashes or arbitrary execution.
- Command payloads generated by COWL that could result in permanent hardware lockup or EEPROM degradation.
- Insecure local IPC or socket permissions in the application layer.

### Out of Scope
- Circumvention of anti-cheat software or game protections.
- Bypassing digital rights management (DRM) or proprietary licensing.
- Extraction or defeat of proprietary firmware signing keys.
- Attacks requiring physical disassembly or electrical tampering with the target controller.
